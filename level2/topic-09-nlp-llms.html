NLP & Large Language Models

A language-model system is a chain of contracts: text becomes tokens, an objective shapes a conditional distribution, adaptation changes either the context or some weights, decoding turns probabilities into an output, and evaluation asks whether that output is useful and safe. Clear reasoning means naming the unit at every stage—bytes, tokens, examples, parameters, probabilities, or human decisions—rather than treating “the model” as one mysterious object.

Learning outcomes
  • Describe BPE, WordPiece, SentencePiece, Unigram tokenization and their tradeoffs.
  • Explain next-token prediction and its emergent consequences; compare encoder-only (BERT), decoder-only (GPT), encoder-decoder (T5); contrast contextual vs static embeddings.
  • Explain in-context learning and few-shot prompting; compare full fine-tuning, LoRA/QLoRA, adapters, prefix-tuning by cost and effect; describe instruction tuning.
  • Explain decoding strategies (greedy, beam, top-k, top-p, temperature); describe hallucination's mechanistic causes and mitigations.
  • Apply evaluation methods (perplexity, benchmarks, LLM-as-judge) and their limits; diagnose contamination and benchmark gaming.
Orientation — six objects, three phases

Data construction chooses a corpus, normalization, tokenizer, and train/evaluation boundaries. Training or adaptation changes parameters by minimizing a loss. Inference freezes those parameters, supplies a context, and applies a decoding rule. An instruction in a prompt is data consumed at inference; it is not a parameter update.

9.1 Tokenization — the compromise everything else stands on

Purpose — map text to a finite, reversible-enough sequence

Neural networks index finite tables, while language contains open-ended words, names, scripts, numbers, emoji, and code. A tokenizer maps text to IDs and usually provides a decoder back to text. Whole-word vocabularies make rare and novel words difficult; character or byte units cover more strings but lengthen sequences. Subword tokenizers learn reusable fragments between those extremes.

“Lossless” needs a scope. A byte-level configuration whose base vocabulary contains every byte can encode arbitrary byte sequences without an unknown token, but earlier Unicode normalization, lowercasing, accent stripping, whitespace cleanup, or special-token handling can still change the original text. SentencePiece can train without language-specific whitespace pre-tokenization, yet its BPE/Unigram algorithm, normalization, and optional byte fallback are separate choices.

Worked capacity cost

An embedding table with \(|V|=128{,}000\), width \(d=4096\), and two bytes per stored weight uses \(128{,}000\times4096\times2=1{,}048{,}576{,}000\) bytes, about \(0.98\) GiB. If input embedding and output projection weights are untied, that vocabulary-related weight cost is roughly doubled. A larger vocabulary can shorten sequences but enlarges these matrices and may leave rare tokens poorly trained.

BPE from counts — merge adjacent symbols, then replay the merge order

A common word-boundary BPE teaching version begins with characters plus an end-of-word marker. Count adjacent pairs weighted by word frequency, merge the most frequent pair, update the corpus, and repeat. Tokenization later replays the ordered merge rules; storing only the final token strings is insufficient when candidate merges overlap. Byte-level BPE changes the starting alphabet to byte symbols but keeps the iterative merge idea.

Two merges by hand

In the tiny corpus “low low lower,” pairs \(l\,o\) and \(o\,w\) each occur three times. If the documented tie-break chooses (l,o), merge 1 creates lo. Then lo–w occurs three times, so merge 2 creates low. Different deterministic tie-breaking can produce a different but valid merge list; production tokenizers must version that list.

TRAIN_BPE(weighted_words, merge_budget):
  represent each word as base symbols plus END_OF_WORD
  merge_rules = []
  repeat up to merge_budget times:
      count every adjacent symbol pair, weighted by word frequency
      if no pair remains: stop
      best_pair = highest count, then documented deterministic tie-break
      replace every non-overlapping occurrence of best_pair with its concatenation
      append best_pair to merge_rules
  return base vocabulary and ordered merge_rules

TOKENIZE_BPE(text, merge_rules):
  split with the tokenizer's documented boundary rule
  represent each unit with the same base symbols
  replay merge_rules in order
  map final symbols to IDs

    9.2 Pretraining and the three architectures

    Objectives — specify what is visible when each target is predicted

    A causal language model minimizes mean negative log-likelihood over predicted positions:

    $$\mathcal L_{causal}=-\frac1N\sum_{t\in\mathcal T}\log p_\theta(x_t\mid x_{<t}).$$

    The causal mask prevents a target from reading itself or later tokens. A masked-language model instead predicts selected corrupted positions using left and right context. A denoising encoder–decoder corrupts spans or sequences and autoregressively reconstructs targets while cross-attending to an encoded input. Masking, corruption rate, loss normalization, and which positions count in \(N\) are part of the objective.

    What next-token pressure can and cannot imply

    Reducing loss across diverse text rewards representations of syntax, entities, discourse, code, and many recurring reasoning patterns because those structures improve prediction. It does not directly optimize truth, causal understanding, harmlessness, or task completion. Smooth loss improvement can also cross an evaluation threshold and look like a sudden capability; study both continuous metrics and behavior, rather than treating every “emergence” claim as the same theorem.

    Encoder-only, decoder-only, and encoder–decoder information flow

    Shape and cost ledger

    With batch \(B=4\), source length \(n_s=512\), target length \(n_t=128\), and width \(d=768\), encoder states are \([4,512,768]\) and decoder states are \([4,128,768]\). Per head, encoder self-attention has \(512^2\) score positions per example, decoder self-attention has \(128^2\), and cross-attention has \(128\times512\). Padding masks and causal masks act on different axes.

    Cross-entropy, perplexity, and bits per byte — keep the denominator

    If the correct next-token probabilities are \(p_1,\ldots,p_N\), mean cross-entropy is \(H=-N^{-1}\sum_i\log p_i\) nats/token and perplexity is \(\exp(H)\). Perplexity is the geometric mean inverse probability assigned to observed tokens; it is not a literal count of plausible English words. Bits per token is \(H/\log2\). For the same raw byte stream, total negative log probability divided by bytes gives bits per byte, which is more meaningful across tokenizers—yet preprocessing, context boundaries, and evaluation data must still match.

    Worked likelihood

    For correct-token probabilities \([0.5,0.25,0.125,0.5]\), total negative log-likelihood is \(4.852\) nats and \(H=1.213\) nats/token. Thus perplexity is \(e^{1.213}\approx3.364\), or \(1.75\) bits/token. If those predictions cover the same eight raw bytes, total cross-entropy is seven bits and the rate is \(0.875\) bits/byte.

    Guided calculation — token likelihood and compression units

    Probabilities must be in \((0,1]\). Masked models require a separately specified pseudo-likelihood protocol; their masked loss should not be silently compared with a causal model's left-to-right perplexity.

    Static and contextual embeddings answer different questions

    A static embedding method assigns one learned vector to each vocabulary item: “bank” begins with the same vector in “river bank” and “bank loan.” A contextual model computes a hidden state for each occurrence from the entire visible context, so those two states may differ. Layer, pooling, prompt, and fine-tuning objective determine what a contextual vector represents; a raw mean of token states is not automatically a strong sentence embedding.

    Cosine is geometry, not probability

    For vectors \(a=[1,2]\) and \(b=[2,0]\), cosine similarity is \(a^\top b/(\|a\|\|b\|)=2/(\sqrt5\cdot2)\approx0.447\). That number ranks angular similarity under this representation; it is not a \(44.7\%\) probability of semantic equivalence. Validate pooling and thresholds on the retrieval/classification task and population of interest.

    Architecture and pretraining decision guide

    Start with the information pattern. If every input token may use both sides and output is a label or embedding, an encoder is efficient. If the product emits an open-ended continuation, a causal decoder matches inference. If a bounded source conditions a distinct target, encoder–decoder separation can make source processing and cross-attention explicit. Data, tokenizer, parameter count, and serving constraints often matter as much as the family name.

    Common failures

    A causal mask accidentally omitted during training leaks targets. Padding included in the loss rewards predicting padding. Random document concatenation creates artificial cross-document dependencies. Duplicate train/evaluation passages inflate loss and benchmark results. A lower average pretraining loss can hide worse performance on a language, domain, long-context region, or downstream requirement, so retain slice-level evaluation.

    9.3 Adapting a base model

    In-context learning — change activations, not stored parameters

    A zero-shot prompt describes a task without demonstrations; a few-shot prompt includes examples. The model conditions on those tokens and computes new activations, but its weights remain fixed. In-context learning can infer formats, label mappings, styles, or task patterns already supported by pretraining. It does not certify that the model learned a durable rule, and the effect usually ends when the context is removed.

    Prompt componentPurposeFailure mode to test
    task and audiencestate the decision and intended readerunderspecified objective or inappropriate detail
    input boundariesseparate instructions, untrusted content, examples, and evidenceprompt injection or treating quoted text as authority
    output contractdefine fields, units, allowed labels, length, and abstentionvalid-looking but semantically invalid output
    demonstrationsshow edge cases and desired mappingorder, recency, majority-label, and surface-format bias
    evidencesupply current task facts separately from instructionsunsupported claims or conflict between sources

    Use representative examples with correct rationales only when the rationale itself is desired. Shuffle or counterbalance order during evaluation, test paraphrases, and retrieve examples by task relevance rather than filling context indiscriminately. A system prompt influences behavior but is not a security boundary against malicious content or tool misuse.

    Context budgeting — reserve output and failure margin before examples

    If a model supports \(C\) tokens, a planning budget is \(R=C-S-Q-O-M\), where \(S\) is system/tool-schema material, \(Q\) is the current query and evidence, \(O\) is reserved output, and \(M\) is a safety margin for tokenizer and template variation. If each demonstration costs \(E\) tokens, at most \(\lfloor R/E\rfloor\) whole examples fit under this simplified accounting. APIs differ in whether output shares the advertised window, so verify the deployed contract.

    Capacity is a ceiling, not a target. More demonstrations can distract the model, push crucial instructions into weak positions, increase latency, or include misleading analogies. Measure marginal task gain per added token.

    Full fine-tuning and PEFT — count the matrices that actually update

    Full fine-tuning updates every selected base parameter and offers the most degrees of freedom, but it stores optimizer state and gradients for a large parameter set and can overfit or forget useful behavior. Parameter-efficient fine-tuning (PEFT) freezes most base weights and trains smaller modules. For a matrix \(W\in\mathbb R^{d_{out}\times d_{in}}\), LoRA uses \(\Delta W=(\alpha/r)BA\), with \(B\in\mathbb R^{d_{out}\times r}\) and \(A\in\mathbb R^{r\times d_{in}}\). It trains \(r(d_{in}+d_{out})\) values rather than \(d_{in}d_{out}\).

    Worked LoRA count

    Target four \(4096\times4096\) matrices in each of 32 layers with rank \(r=16\). Each matrix adds \(16(4096+4096)=131{,}072\) trainable values. Total LoRA values are \(131{,}072\times4\times32=16{,}777{,}216\), about \(0.240\%\) of a 7-billion-parameter base. This percentage depends on the target modules; “rank 16” alone does not determine it.

    Instruction tuning and the adaptation decision

    Supervised instruction tuning trains on structured pairs such as instruction, optional context, and desired response, commonly masking prompt tokens so loss focuses on the response. It teaches response conventions and task behavior represented in its data; it does not automatically update changing facts, prove correctness, or capture every acceptable answer. Mixture weights, duplicate templates, response length, refusal examples, and annotator policy can dominate outcomes.

    9.4 Decoding — how a distribution becomes text

    Temperature — rescale logits before normalization

    Given logits \(z_i\), temperature \(T>0\) produces \(p_i(T)=\exp(z_i/T)/\sum_j\exp(z_j/T)\). Lower \(T\) sharpens unequal logits; higher \(T\) flattens them; \(T=1\) preserves the model's original softmax distribution. The limit as \(T\to0^+\) concentrates on the maximum logit, but implementations usually select argmax directly rather than divide by zero. Temperature does not add knowledge or recalibrate a miscalibrated model.

    Worked softmax

    For logits \([2,1,0]\), subtracting the maximum gives weights \([1,e^{-1},e^{-2}]\), so at \(T=1\) probabilities are approximately \([0.665,0.245,0.090]\). At \(T=0.5\), effective logits are \([4,2,0]\) and probabilities become about \([0.867,0.117,0.016]\). The rank is unchanged, but probability mass is more concentrated.

    Hallucination — plausible form without sufficient support

    A hallucination is an output presented as supported or factual when it conflicts with the source, world, or task constraints. Several mechanisms can contribute: predictive training rewards likely text rather than verified claims; relevant evidence may be absent, weakly represented, stale, or inaccessible in context; ambiguous prompts invite an unsupported completion; retrieved passages can be wrong or conflicting; and one generated error conditions later tokens. Greedy decoding can hallucinate, while sampling can change which unsupported claim appears.

    Fluent wording, a high sequence probability, repeated self-consistency, or agreement between related models can all occur on a shared misconception. Estimate calibration on the deployed task, define an abstention path, and measure unsupported-claim rate separately from style quality.

    9.5 Evaluation — the hardest problem in the room

    Purpose — evaluate the decision system against a frozen contract

    Evaluation starts by defining the deployment distribution, unit of analysis, acceptable errors, and decision threshold. A base-model test may isolate token prediction; a product test should also include tokenizer, prompt, retrieval, tools, decoder, safety filters, latency, and cost. Report means with counts and uncertainty, plus slices for language, difficulty, length, subgroup, time, and source.

    LayerExample measuresWhat it misses alone
    predictive distributionNLL, perplexity, bits/byte, calibrationinstruction usefulness, safety, and task-specific harm
    task outputexact match, F1, pass rate, retrieval recall, grounded-claim ratevalid alternate answers and unequal error cost unless designed in
    human judgmentrubric scores, blinded pairwise preference, error severityannotator disagreement, fatigue, cultural/policy assumptions
    system operationlatency percentiles, token/tool cost, schema validity, refusal/escalation ratesemantic correctness unless joined with quality labels
    riskprivacy leakage, harmful completion, jailbreak, subgroup failureunknown attacks and consequences outside the tested threat model

    Benchmarks and uncertainty — standardized is not deployment-valid

    Benchmarks enable controlled comparisons when prompts, few-shot examples, decoder, scoring, and versions match. They do not establish fitness for a different product population. Exact-match can reject valid paraphrases; execution tests cover only their cases; multiple-choice accuracy can be sensitive to label ordering and guessing. Inspect cases, define scoring before results, and report confidence intervals or paired uncertainty rather than ranking tiny score differences as certain.

    Worked sampling uncertainty

    A model correct on 72 of 100 independent-looking cases has observed accuracy \(0.72\). A rough normal standard error is \(\sqrt{0.72(0.28)/100}\approx0.045\), giving an approximate 95% interval \(0.72\pm1.96(0.045)\approx[0.63,0.81]\). Exact/binomial or bootstrap intervals may be preferable, and clustered/repeated items reduce the effective independence assumed by this shortcut.

    For code, pass@\(k\) asks whether at least one of \(k\) candidates passes tests. Under an idealized independent per-sample success probability \(p\), this chance is \(1-(1-p)^k\); real candidates are correlated, and the empirical estimator depends on how many samples were drawn. Always publish sample count, temperature, test suite, sandbox, and estimator.

    LLM-as-judge — scalable labels require calibration and counterbalancing

    A model judge can apply a rubric to many outputs or compare pairs, but it may prefer the first/last answer, longer prose, familiar style, its own model family, or content that echoes the reference. Blind system identity, randomize and reverse pair order, request structured criterion-level scores, separate style from correctness, and calibrate against qualified humans on representative cases. Agreement is evidence about a protocol, not proof that the judge is objective.

    Guided calculation — detect position sensitivity in pairwise judging
    Give ties half credit to A, compare A's score when shown first versus second, and inspect the gap.
    A score shown first 75.0% A score shown second 50.0% pooled counterbalanced score 62.5% absolute position gap 25.0 percentage points

    The gap is a diagnostic, not automatically a causal estimate: case mix, sampling noise, and judge stochasticity must also be controlled. Use matched cases in both orders when practical and report human agreement by criterion.

    Contamination, benchmark gaming, and a defensible evaluation protocol

    Contamination occurs when evaluation items, close variants, solutions, or strongly identifying metadata influence training or adaptation. Exact hashes catch exact copies; normalized n-grams, MinHash, code structure, and semantic retrieval can find near duplicates, each with false positives and false negatives. A high score on an old public set or a drop on fresh variants is a warning signal, not proof of a particular training overlap without further evidence.

    Benchmark gaming is broader: repeated tuning on a public leaderboard, selecting a prompt after inspecting test errors, exploiting formatting artifacts, reporting only favorable subsets, or training on synthetic variants tailored to the test can overfit the protocol without explicit item copies. The final test becomes training data once its results steer another change.

    Parameter-efficient fine-tuning: adapt a subset or added modules while most base weights remain frozen.
    log probability
    \(\log p\); sequence log probabilities add, avoiding products of many tiny probabilities.
    exposure bias
    A train/inference mismatch: gold prefixes during teacher-forced training versus model-generated prefixes at inference.
    calibration
    Whether stated confidence or predicted probability matches empirical frequency under a defined task.
    contamination
    Evaluation information influencing training/adaptation, directly or through close variants and solutions.

    Self-check

    1. Which statement distinguishes the tokenizer families most accurately?

    b. Algorithm, training framework, base alphabet, normalization, and byte fallback are separate choices. Byte coverage cannot undo earlier lossy normalization.

    2. A multilingual tokenizer averages 1.2 tokens/word in language A and 3.0 in language B. What is the defensible conclusion?

    d. Fertility exposes a real resource disparity, but it does not alone identify its cause or downstream effect.

    3. Correct-token probabilities are \([0.5,0.25,0.125,0.5]\). What are mean NLL and perplexity?

    c. Sum \(-\log p_i=4.852\), divide by four, then exponentiate. The 1.750 figure is bits/token, not nats/token.

    4. Which architecture/embedding statement is correct?

    a. Masks and objective determine information flow. Masked filling can generate iteratively, and cosine needs task-specific validation rather than probabilistic interpretation.

    5. With \(C=8192\), \(S=400\), \(Q=600\), \(O=1000\), \(M=512\), and \(E=350\), how many whole demonstrations fit under the simplified budget?

    b. \(R=5680\), so \(\lfloor5680/350\rfloor=16\), leaving 80 tokens. Capacity does not imply all 16 help.

    6. Four square \(4096\times4096\) matrices in each of 32 layers receive rank-16 LoRA updates. How many trainable LoRA values are added, and what does instruction tuning add conceptually?

    d. Each square matrix adds \(2rd=131{,}072\) values, times \(128\) matrices. Instruction tuning shapes behavior; it is not a freshness or correctness guarantee.

    7. For sorted probabilities \([0.40,0.30,0.15,0.10,0.05]\), which top-p set is selected at \(p=0.80\)?

    c. The first two sum to 0.70; adding 0.15 crosses the threshold at 0.85, after which the retained set is renormalized.

    8. A grounded summarizer invents a number despite greedy decoding. Which response best fits the mechanism?

    a. Decoding changes the path through a distribution; it cannot supply missing evidence or guarantee truth.

    9. A scores 75% with half-credit ties when shown first and 50% when shown second on counterbalanced cases. What should be reported?

    b. Order sensitivity is material evidence about the judging protocol. It should not be hidden inside one aggregate.

    10. A model excels on an old public benchmark and drops on fresh variants. What is the sound next step?

    d. The score pattern has several possible causes. Decontamination evidence and disciplined new holdouts distinguish them better than an absolute claim.
